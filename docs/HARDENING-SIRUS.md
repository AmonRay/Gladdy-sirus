# Граничные случаи и жизненный цикл — Gladdy 2.43

> Актуализация без повышения версии 2.44: последующие исправления кликов, DR, таймеров, включения модулей и предварительной проверки размера zlib описаны в [AUDIT-FIXES-SIRUS.md](AUDIT-FIXES-SIRUS.md). Прежнее ограничение проверки размера только после распаковки устранено; исторический отчёт ниже сохранён.

> Изменение процесса после 2.44: GitHub CI удалён, тесты запускаются локально. В Actions оставлена только публикация релиза при изменении версии `.toc` в `main`. Исторические результаты CI ниже относятся к проверке соответствующего выпуска. Версию повышать только по прямой просьбе владельца.

## Изменения

### Импорт и экспорт

Окна AceGUI создаются независимо при первом открытии и затем переиспользуются. Фоновое декодирование встроенных профилей не создаёт окон. Сериализованная и сжатая строки экспорта больше не удерживаются в переменных уровня файла.

Исправлены два подтверждённых дефекта: прежняя ветка `errorFound` не возвращала отказ при несовместимом типе; после изменения корректной строки на некорректную мог оставаться ранее подготовленный профиль. Редактирование, очистка и закрытие теперь сбрасывают кандидата, а кнопка применения повторно проверяет данные до записи.

До применения целиком проверяются root, версия, типы известных настроек, ключи, конечность чисел, циклы и глубина. Ошибка не приводит к частичному обновлению. Входная таблица при валидации не изменяется. Сохранена совместимость с неизвестными старыми скалярными полями; неизвестные вложенные карты не создаются при применении. Удалённые ключи пропускаются по точному совпадению. Карты, специфичные для дополнения, фильтруются только на корневом уровне при импорте другого дополнения.

Ограничения: кодированная строка — 512 КиБ; распакованные сериализованные данные — 2 МиБ; глубина — 32; записей — 50 000; токенов — 120 000. Структура wire-формата проверяется до рекурсивного AceSerializer, лишние корни и хвост сжатых данных отклоняются.

**Ограничение защиты:** размер распакованной строки проверяется после завершения `LibDeflate:DecompressZlib`. Публичный API используемой общей библиотеки не предоставляет bounded/streaming inflate. Это не полная защита от decompression bomb и не гарантия ограниченной пиковой памяти при распаковке. Общая библиотека не форкалась. Не следует импортировать недоверенные строки.

Проверены все девять профилей из `ImportStrings.lua`, но не произвольный корпус пользовательских экспортов. `GladdyXZ` и формат экспорта не менялись.

### Отсутствующие заклинания

Локализованные ключи констант строятся через общий для Gladdy helper. Временный sentinel удаляется до передачи таблиц потребителям. При отсутствии имени запись не заменяется придуманным названием. Числовые ID тотемных импульсов сохраняются. Составные имена и `altName` тоже проверяют все исходные spell IDs. При доступных данных все таблицы, возвращаемые getter-функциями констант, совпадают с 2.42; это проверено локальным сравнением с master.

Инициализация объявлений пропускает отсутствующие названия в наборе воскрешений. Список DR-иконок пропускает отсутствующие текстуры. Подписи кулдаунов и тотемов могут отображать числовой ID вместо отсутствующего имени; ID не используется как выдуманный локализованный ключ. При включении выводится сводка недоступных ID, обнаруженных helper-ом. Это диагностический список, а не полный probe всех spell IDs аддона.

Автотесты проверяют полностью доступный, частично отсутствующий и полностью отсутствующий набор имён для констант и затронутых модулей. Они не доказывают успешную загрузку всех сторонних библиотек при искусственном отсутствии всех заклинаний и не подтверждают фактическое наличие ID или серверные CD/DR на Sirus.

### Combat lockdown

Создание контейнера и защищённых кнопок проверяет lockdown до выделения фреймов. Вход на арену, тестовые фреймы и регистрация Clique откладываются до `PLAYER_REGEN_ENABLED`. Повторный запрос не создаёт дубликатов; отмена теста/выход с арены отменяют отложенный показ. При возобновлении входа используется полный путь `JoinedArena`, включая восстановление alpha и настройку скрытия Blizzard frames.

Моки запрещают создание любого фрейма во время боя и проверяют последующее создание secure-кнопок. Это проверка логики, не доказательство отсутствия taint в клиенте.

### TotemPlates

Перед добавлением фрейма и hooks проверяется ожидаемая legacy-структура nameplate. Повторное присоединение не выделяет второй комплект. Неизвестная структура, пустой текст или отсутствующая настройка тотема не приводят к обращению к nil. Это fail-closed guard, а не новая реализация DF nameplates; для неизвестной структуры иконка не создаётся.

## Общие библиотеки

AceGUI/AceConfig/SharedMediaWidgets остаются общими через LibStub: без `-Gladdy`, дополнительных pools или префиксов. В этом выпуске содержимое `Gladdy/Libs` не менялось. Проверка всех 58 исходных/установленных hashes остаётся в CI. Решение по ElvUI RefreshTree из 2.42 сохранено; см. [ACE-SIRUS.md](ACE-SIRUS.md).

## Автономные проверки

Lua 5.1: 37 регрессий Sirus, 9 библиотечных, 8 Ace core, 13 + 12 shared UI в обоих порядках загрузки, 18 импорта, 15 lifecycle/nameplates, 7 × 3 spell-data — всего 133 сценария. Дополнительно: 95 Lua-файлов, 101 TOC/XML dependency, 58 hashes и два синтетических operation-count benchmark. Команды находятся в README и GitHub Actions.

## Приёмка на клиенте

1. Резервная копия WTF, обновление файлов, `/console scriptErrors 1`, `/reload`.
2. Открыть ElvUI и Gladdy в разных порядках с ElvUI/WeakAuras и без них; проверить дерево, подписи, скины. Повторить визуальный сценарий исходного скриншота.
3. Первый вызов export/import, повторное открытие, старый собственный экспорт; затем заменить корректную строку повреждённой и убедиться, что применить её нельзя.
4. Проверить сводку отсутствующих spell IDs на текущем клиенте и реальные spec/CD/DR по логам. Сохранить язык профиля при сравнении.
5. Перезагрузка/вход в combat на арене, окончание боя, отмена теста до regen, вход в реальный матч после теста. Проверить taint/blocked actions, Clique и bindings.
6. Тотемы соперника/союзника на фактических nameplates Sirus с ElvUI и без него, скрытие/повторное появление, отключение модуля.

Клиент Sirus здесь недоступен. FPS, память клиента, визуальная корректность и отсутствие taint не измерялись. Открытые направления: полноценный DF nameplate lifecycle, миграция локализованных ключей профилей, bounded inflate, серверная верификация CD/DR и профилирование повторных font/color/alpha writes.
